# RangeReclaim

Самостоятельная стратегия TradeJS для возврата внутрь диапазона после неудачного
пробоя. Пакет `@tradejs/strategy-range-reclaim` экспортирует одну стратегию
`RangeReclaim` через стандартный `strategyEntries`. Исходная структура взята из
`tradejs-strategy-template`.

Пакет публикуется через стандартный процесс TradeJS: проверенный beta-кандидат,
затем стабильная версия. Лицензия пакета — `UNLICENSED`. Проверки используют
зафиксированные в `yarn.lock` зависимости и Yarn PnP.

## Правила

Входные свечи должны быть полностью закрытыми. `timestamp` означает время начала
свечи в миллисекундах UTC. Допустимы пары `INTERVAL/RANGE_RECLAIM_RANGE_INTERVAL`
`15/240`, `15/60` и `60/240`. Интервалы в конфигурации задаются минутами.

Движок собирает старшую свечу из последовательных младших свечей. Диапазон
считается доступным с начала следующей старшей свечи и остаётся неизменным до
следующего обновления. Например, диапазон 00:00 до 04:00 UTC впервые применяется
к свече 04:00, а свеча 03:45 ещё проверяется относительно предыдущего диапазона.
Уровень должен существовать до начала сигнальной свечи. Последняя младшая свеча
старшего периода никогда не торгует экстремумы собственного периода.

Для диапазона нужны все младшие свечи с начала старшего периода. При частичном
начале истории или пропуске свечей движок ждёт новый полный период. Пропуск
сбрасывает диапазон, ожидание и ATR. Диапазон нулевой ширины непригоден.

LONG начинается при `low < range.low`, SHORT при `high > range.high`. Касание
границы пробоем не считается. Подтверждение требует
`range.low < close < range.high`. Форма тела, тени и объём значения не имеют.
Закрытие внутри допустимо на свече выхода и на следующих `WAIT_BARS` свечах.
`WAIT_BARS=0` разрешает только возврат на той же свече. Свеча ровно на сроке
ожидания ещё может подтвердить возврат. Новые экстремумы срок не продлевают.

Обновление диапазона отменяет незавершённый сигнал до проверки новой свечи.
Пересечение обеих границ одной свечой закрывает попытку на весь текущий диапазон,
поскольку порядок движения внутри OHLC неизвестен. При ожидании LONG выход выше
верхней границы также закрывает попытку, а для SHORT правило симметрично.
Истечение ожидания и превышение допустимой глубины закрывают попытку до следующего
диапазона. Глубина измеряется от пробитой границы до худшего экстремума всего
выхода и делится на ширину исходного диапазона. Равенство пределу разрешено.

На исходный диапазон допускается максимум одна подтверждённая попытка входа.
Отклонение по риску, отключённое направление, уже открытая позиция или отклонение
исполнения не дают повторной попытки. Правило намеренно строже одного заполненного
входа. Оно исключает зависимость детектора от результатов исполнения. При
открытой позиции новые входы, усреднение и разворот отсутствуют.

Стоп LONG равен минимуму за всё ожидание минус ATR-буфер. Стоп SHORT равен
максимуму плюс ATR-буфер. ATR рассчитывается по младшим закрытым свечам, включая
подтверждающую свечу. Начальное значение есть среднее первых `ATR_LENGTH` true
range, затем используется сглаживание Уайлдера. До полного прогрева входов нет.

Цель фиксируется при входе в середине исходного диапазона (`midpoint`) либо на
противоположной границе (`opposite`). Стоп и цель после входа не перестраиваются
при обновлении диапазона. Цель за спиной у цены и неположительный стоп запрещены.
Проверка `minRiskRatio` использует чистую прибыль и риск с комиссиями,
проскальзыванием и влиянием на цену. Равенство минимальному отношению разрешено.
Количество равно `MAX_LOSS_VALUE / lossPerUnit` из общего расчёта Strategy Kit.

Через `MAX_HOLD_BARS` интервалов от сигнальной свечи core запрашивает выход через
`StrategyAPI.exit`. Срок считается по времени, поэтому пропуски его не продлевают.
Фактические заявки, округление количества, стоп и тейк исполняет общий TradeJS
runtime. По умолчанию историческое исполнение отложено на одну свечу и использует
её открытие. Проверка риска на закрытии сигнала не гарантирует такое же отношение
при заполнении после ценового разрыва.

## Исследовательские настройки

Все численные значения ниже являются начальной исследовательской гипотезой.
Доходность на Bybit не проверялась.

| Поле                                          | По умолчанию | Значение                                        |
| --------------------------------------------- | ------------ | ----------------------------------------------- |
| `INTERVAL`                                    | `15`         | Младший интервал в минутах.                     |
| `RANGE_RECLAIM_RANGE_INTERVAL`                | `240`        | Старший интервал в минутах.                     |
| `RANGE_RECLAIM_WAIT_BARS`                     | `1`          | Число дополнительных свечей на возврат.         |
| `RANGE_RECLAIM_MAX_DEPTH_RATIO`               | `0.25`       | Максимальная глубина как доля ширины диапазона. |
| `RANGE_RECLAIM_ATR_LENGTH`                    | `14`         | Период ATR.                                     |
| `RANGE_RECLAIM_STOP_ATR_BUFFER`               | `0.1`        | Буфер за экстремумом в ATR.                     |
| `RANGE_RECLAIM_TARGET`                        | `midpoint`   | Середина либо противоположная граница.          |
| `RANGE_RECLAIM_MAX_HOLD_BARS`                 | `16`         | Срок удержания в младших интервалах.            |
| `LONG.minRiskRatio`, `SHORT.minRiskRatio`     | `1`          | Минимальное чистое отношение прибыли к риску.   |
| `MAX_LOSS_VALUE`                              | `10`         | Расчётный денежный риск для исследования.       |
| `RISK_FEE_RATE`                               | `0.001`      | Односторонняя комиссия в долях, то есть 0.1%.   |
| `RISK_SLIPPAGE_BPS`, `RISK_MARKET_IMPACT_BPS` | `0`          | Дополнительные расходы в базисных пунктах.      |
| `BACKTEST_ENTRY_DELAY_BARS`                   | `1`          | Задержка исторического заполнения.              |

Оба направления включены. AI и ML выключены. Фильтры тренда, объёма, формы тени
и дополнительные зоны не добавлены. Ограничения глубины и срока прямо задают,
какой выход считать неудачным пробоем, и ограничивают длительность сделки.

`LiquidityTails` создаёт зону по характерной тени и ищет её повторную проверку.
`StructureZones` использует зоны поддержки и сопротивления из поворотных точек.
RangeReclaim использует заранее закрытую старшую свечу независимо от формы теней
и структуры поворотных точек. Состав CopyTrading оставлен без изменений.

## Дополнительная проверка доли затрат

`RANGE_RECLAIM_MAX_COST_SHARE` ограничивает отношение расчётных затрат к валовой
прибыли до цели. Расчёт использует
`roundTripEntryTargetCostPerUnit / grossRewardPerUnit` из Strategy Kit с прежними
`RISK_*` параметрами. Допустимы значения от 0 до 1, где 0 отключает проверку,
а равенство положительному пределу допускается. Превышение возвращает
`RANGE_RECLAIM_COST_SHARE` и расходует попытку на исходный диапазон.

Проверка по умолчанию выключена и сохраняет прежние торговые решения. При
включении расчёт размера и проверка чистого отношения прибыли к риску сохраняются,
а `additionalIndicators.costShare` содержит рассчитанную долю затрат. Проверка
позволяет отдельно исследовать сделки, у которых большая часть ожидаемой прибыли
уходит на затраты. Положительный core с проверкой не получен, поэтому порог
остаётся исследовательским параметром.

Снимки состояния привязаны к полной конфигурации, поэтому после добавления поля
прежние снимки не совместимы. Воспроизведение истории с нулевым порогом сохраняет
прежние торговые решения.

## Срок исходного диапазона

`RANGE_RECLAIM_MAX_SOURCE_AGE_BARS` ограничивает время подтверждения возврата
в младших интервалах. Значение 0 отключает проверку и сохраняет прежние решения.
При положительном значении подтверждение должно иметь
`timestamp < range.end + MAX_SOURCE_AGE_BARS * step`, где `step` равен длительности
младшей свечи. Равенство сроку отменяет ожидание и расходует попытку с кодом
`RANGE_RECLAIM_SOURCE_EXPIRED`. Новый исходный диапазон получает свой срок.
Прежний срок `WAIT_BARS` также действует и никогда не продлевается.

На 15m/4h значение 4 допускает подтверждение на первых четырёх закрытых 15m
свечах после закрытия исходной 4h-свечи. Например, при `range.end=04:00 UTC`
допустимы свечи с временем начала 04:00, 04:15, 04:30 и 04:45. Свеча 05:00
уже просрочена. Выход за границу на 04:45 не может подтвердиться на 05:00,
даже если `WAIT_BARS` ещё разрешал бы ожидание. Уровни открытой старшей свечи
не используются, а срок восстанавливается из сохранённого исходного диапазона.
Численное значение является исследовательским параметром.

## Замороженные примеры исследования за 730 дней

`examples/research-730d-15m-grid.json` содержит выбранную исследовательскую
конфигурацию 15m/4h со сроком диапазона 4, удержанием 16 и долей затрат 0.01.
`examples/research-730d-1h-grid.json` сохраняет прежнюю конфигурацию 1h/4h
с удержанием 8 и долей затрат 0.01. В ней срок диапазона по умолчанию равен 0.
Оба направления включены. Проверка затрат использует `RISK_FEE_RATE=0.001`
для расчёта допустимости и размера; это отдельное поле от комиссии симуляции.

Период исследования равен `[2024-10-09T00:00:00Z, 2026-10-09T00:00:00Z)`.
Состав 577 инструментов на 15m и 574 на 1h взят из одного текущего списка
production. Только 244 инструмента имеют полную историю всего периода.
Эти примеры предназначены для ретроспективного исследования и не доказывают
доходность или историческую устойчивость всего рынка. Настройки 1h с новыми
ограничениями отклонены из-за отрицательных коротких периодов.

Все операционные команды, точные списки тикеров, комиссии симуляции, модель
проскальзывания и результаты принадлежат `tradejs-project`. Примеры не добавляют
пакет в общую композицию и не меняют runtime. Будущий повтор выполняется
из Project с `--cacheOnly`, замороженными списками и тем же окном.

## Восстановление и график

`createRangeReclaimEngine({ config, initialCandles })` восстанавливает детектор
повторением тех же переходов, что выполняет `next(candle)`. `getState()` возвращает
отдельную копию JSON-совместимого состояния. Альтернативно можно передать этот
снимок через `state`. Изменение конфигурации делает снимок несовместимым.
Повторный `timestamp` не меняет состояние, более ранняя свеча отвергается.
Состояние ограничено текущей старшей свечой, одним диапазоном, ATR и одним сигналом.

Core хранит JSON-состояние через `StrategyAPI.createStateController`, включая
использованный диапазон, последнюю обработанную свечу и время сигнала входа.
Ключ учитывает полную разрешённую конфигурацию. При восстановлении checkpoint
сохраняются срок удержания и запрет повторного входа. Повтор одной свечи в core
возвращает `skip`, чтобы не повторять действие.

Холодный запуск по истории восстанавливает сигналы детектора, но не фактические
биржевые заполнения. В публичном `Position` нет времени открытия. Если открытая
позиция есть, а checkpoint с временем входа отсутствует, стратегия запрашивает
выход с кодом `RANGE_RECLAIM_UNKNOWN_POSITION_AGE`. Полное восстановление открытой
позиции требует сохранённого lifecycle checkpoint хоста.

Фигуры в решении входа содержат исходный диапазон, обе границы и середину.
Отдельно показаны начало выхода, худший экстремум, подтверждение возврата, вход,
стоп и цель. Подтверждение и вход могут совпадать по координатам. Фигуры отражают
сигнал, фактическое заполнение после задержки показывает общий runtime.

## Подключение и будущий бэктест

После установки локального архива пакета в отдельный исследовательский Project
добавьте его в список `strategies` вашей конфигурации:

```ts
import { defineConfig } from "@tradejs/core/config";

export default defineConfig({
  strategies: ["@tradejs/strategy-range-reclaim"],
});
```

При добавлении к существующей композиции сохраните её preset, connectors,
indicators и runtime. Готовый пример с проверкой типов находится в
`examples/registration.ts`. Текущий `tradejs-project` в рамках этой задачи не
менялся. Пакет не опубликован в npm, поэтому установка по одному имени пока
невозможна.

Файл `examples/backtest-grid.json` содержит единственную полностью заданную
конфигурацию 15m/4h в формате Redis backtest grid. Каждое поле содержит массив
из одного значения, поэтому подбора параметров нет. Перед будущим запуском
установите пакет и зарегистрируйте эту конфигурацию под именем
`RangeReclaim:research-v1` в backtest-хранилище Project. В этой задаче Redis
не изменялся. Комиссию и модель исполнения нужно согласовать с будущим прогоном.

Команду выполняйте из `tradejs-project`. Пример фиксирует BTCUSDT, Bybit и
период с 2026-09-01 00:00 UTC до 2026-10-01 00:00 UTC:

```bash
cd /Users/aleksnick/dev/tradejs/tradejs-project
PROJECT_CWD=/Users/aleksnick/dev/tradejs/tradejs-project \
TRADEJS_SOURCE_REPOSITORY_ROOT=/Users/aleksnick/dev/tradejs/tradejs-strategy-range-reclaim \
TRADEJS_FRAMEWORK_REPOSITORY_ROOT=/Users/aleksnick/dev/tradejs/investing \
yarn backtest -c RangeReclaim:research-v1 --connector bybit \
  --tickers BTCUSDT --timeframe 15 \
  --startTime 1788220800000 --endTime 1790812800000 \
  --backtestEntryDelayBars 1 --backtestPriceMode open --cacheOnly --fast -p 1
```

Для 15m/1h измените `RANGE_RECLAIM_RANGE_INTERVAL` на `60` в отдельной копии
конфигурации. Для 1h/4h установите `INTERVAL=60`, старший интервал `240` и
`--timeframe 60`. Срок ожидания и удержания всегда измеряется младшими интервалами.
Результаты и артефакты сохраняйте только в Project. Перед исследованием следует
зафиксировать Git SHA исходника и хоста, checksum конфигурации, версии пакетов,
затраты и доступность кэшированной истории. Отсутствие кэша не разрешает загрузку
новой истории. В данном изменении бэктесты не запускались.

## Проверки

```bash
yarn install --immutable
yarn prettify
yarn checks
```

Проверки включают форматирование, типы, сборку ESM/CJS с декларациями и тесты
LONG/SHORT, границ UTC, отмены сигналов и восстановления состояния. Проверки core
используют настоящий публичный `StrategyAPI` и заменяют только получение позиции
от биржи. `@tradejs/*` остаются peerDependencies с соответствующими devDependencies,
так что состав runtime определяет Project.

Идеи предоставлены пользователем в ссылках
[CRT Liquidity Sweep](https://www.tradingview.com/script/a9lBrLZx-CRT-Liquidity-Sweep-Strategy-SOL-5-MIN/)
и [Sweep & Reverse](https://www.tradingview.com/script/GoeqO1ev-Sweep-Reverse-Liquidity-Sweep-Reversal-Strategy/).
Страницы не удалось прочитать через инструмент браузера. Код и правила написаны
самостоятельно по заданию. Авторские параметры и результаты не использовались
как доказательство доходности.

## Политика входа

`RANGE_RECLAIM_ENTRY_POLICY` по умолчанию равен `off`. Для пары `15/240`
доступны исследовательские политики `purple`, `orange`, `purple-short`,
`intersection` и `union`.

Зелёный вариант `intersection` разрешает только SHORT: возврат должен составлять
не менее 10% ширины диапазона, а ширина должна быть строго больше 6 ATR либо
3475 базисных пунктов относительно цены подтверждения. Политика проверяется
перед входом, независимо от AI. Пакет не включает отдельно обученный AI-gate.
Отклонение входа не создаёт повторную попытку по тому же диапазону.

Численные пороги исследовательские. Историческое сравнение использовало
поздний состав тикеров и уже просмотренный тестовый период; оно не доказывает
устойчивость на новых данных.
